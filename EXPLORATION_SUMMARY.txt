PROJECT OVERVIEW
================================================================================
Das-Tern is a comprehensive healthcare management platform designed for:
- Prescription management with OCR (Optical Character Recognition)
- Medication adherence tracking
- Doctor-patient relationships
- Health vital monitoring
- Khmer language support
- Bakong payment integration (Cambodia)

The backend consists of multiple microservices built with NestJS and Python
FastAPI, all orchestrated with Docker Compose.

BACKEND COMPONENTS EXPLORED
================================================================================

1. MAIN BACKEND (NestJS)
   Location: /backend_nestjs
   Framework: NestJS 10.3.0
   Language: TypeScript
   Port: 3001
   Database: PostgreSQL 17 (Prisma ORM)
   Cache: Redis 7.4
   Queue: RabbitMQ 4.0 (Bull integration)
   
   Key Modules (16 total):
   - Auth: Multi-factor authentication, OAuth, JWT
   - Users: Profile management
   - Connections: Doctor-patient relationships
   - Prescriptions: Core medication management
   - Doses: Medication tracking and adherence
   - Health-Monitoring: Vital signs tracking
   - OCR: Image prescription processing
   - Bakong-Payment: Payment integration
   - Notifications: Multi-channel messaging
   - Email: SendGrid integration
   - Audit: Activity logging
   - Subscriptions: Freemium model
   - Doctor-Dashboard: Analytics
   - Medicines: Drug database
   - Adherence: Metrics reporting
   - Batch-Medication: Time-based grouping

2. BAKONG PAYMENT SERVICE (Microservice)
   Location: /bakong_payment
   Framework: NestJS 10.3.0
   Language: TypeScript
   Port: 3002
   Database: Separate PostgreSQL instance
   
   Functionality:
   - KHQR code generation (Cambodia payment standard)
   - QR code image generation and storage
   - Payment status tracking
   - Subscription management
   - Webhook handling for payment confirmations
   - Multiple payment attempts and retries

3. OCR SERVICE (Python FastAPI)
   Location: /ocr
   Framework: FastAPI
   Language: Python 3.11+
   Port: 8000 (Docker: 8003)
   OCR Engine: Kiri-OCR (Khmer + English support)
   
   Pipeline:
   - Image preprocessing (enhancement, orientation)
   - Text extraction via Kiri-OCR
   - Layout analysis (table detection, region segmentation)
   - Text parsing (structured prescription extraction)
   - JSON response formatting with confidence scores
   
   Capabilities:
   - Extract patient info, medications, dosages, frequencies
   - Support Khmer drug names
   - Calculate extraction confidence
   - Handle PDFs, PNG, JPG, JPEG, WebP formats
   - 10MB file size limit

4. AI-LLM SERVICE (Python FastAPI)
   Location: /ai-llm-service
   Framework: FastAPI
   Language: Python 3.11+
   Port: 8001
   LLM Provider: Ollama (local) or OpenRouter (cloud)
   
   Functionality:
   - OCR result enhancement (correct drug names)
   - Prescription validation
   - Medical safety checks
   - Reminder generation
   - Chatbot interactions
   - Language detection (Khmer/English)
   - Drug advice refusal (safety)

DATABASE ARCHITECTURE
================================================================================

Main Database Models (21 core models):

USER MANAGEMENT:
- Users: Multi-role (PATIENT, DOCTOR, FAMILY_MEMBER)
- Connections: Doctor-patient relationships with permission levels
- ConnectionToken: Invite tokens for secure connection requests

PRESCRIPTION & MEDICATION:
- Prescriptions: Main prescription record with versioning
- Medications: Individual medications within prescriptions
- PrescriptionVersion: Change history and audit trail
- MedicationBatch: Batch/time-based grouping (e.g., "Morning Routine")

DOSE TRACKING:
- DoseEvents: Individual dose records with status tracking
  Status: DUE, TAKEN_ON_TIME, TAKEN_LATE, MISSED, SKIPPED
  Periods: MORNING, AFTERNOON, EVENING, NIGHT

HEALTH MONITORING:
- HealthVitals: Blood pressure, glucose, heart rate, weight, temperature, SPO2
- VitalThresholds: Alert threshold ranges per vital type
- HealthAlerts: Anomaly alerts with severity levels (LOW, MEDIUM, HIGH, CRITICAL)

NOTIFICATIONS & COMMUNICATION:
- Notifications: Multi-channel notifications (in-app, email, push)
- DoctorNote: Doctor-patient communication/notes
- AuditLog: Comprehensive action tracking for compliance

SUBSCRIPTION & BILLING:
- Subscription: Tier management (FREEMIUM, PREMIUM, FAMILY_PREMIUM)
- FamilyMember: Subscription sharing
- (Payment data in separate bakong_payment database)

OTHER:
- MealTimePreference: User meal times for dosage context

Database Constraints:
- All IDs are UUIDs
- Timestamps in UTC with timezone support
- JSON fields for flexible data storage
- Comprehensive indexing for query performance
- Foreign key constraints with cascade delete where appropriate

INTEGRATION FLOWS
================================================================================

OCR PRESCRIPTION CREATION FLOW:
1. Patient uploads prescription image
2. Backend validates file (size, format)
3. Python OCR service extracts text and structures data
4. AI-LLM service enhances results (corrects drug names, validates)
5. Backend merges OCR + AI results
6. Frontend shows preview for user review
7. Patient confirms and creates prescription
8. Dose events automatically generated from prescription schedule
9. Doctor connected if prescription from doctor

DOSE MARKING FLOW:
1. Patient requests daily dose schedule
2. Backend returns DoseEvents for the day grouped by period
3. Patient marks dose as taken (with optional timestamp)
4. Backend calculates if on-time or late
5. Updates DoseEvent status and records timestamp
6. Calculates daily progress
7. If adherence below threshold, alerts connected doctor
8. Sends notifications to patient and connected users

DOCTOR-PATIENT CONNECTION FLOW:
1. Patient generates invite token (20-char unique code)
2. Patient shares via QR code or text
3. Doctor enters token or uses QR scanner
4. Connection request created (PENDING)
5. Patient accepts request
6. Connection status becomes ACCEPTED
7. Doctor can now view patient's prescriptions, doses, vitals
8. Doctor can create/update prescriptions for patient

PAYMENT FLOW:
1. Patient clicks upgrade to premium
2. Frontend calls bakong-payment service
3. Service generates KHQR code and MD5 hash
4. QR image generated and stored
5. Returns QR code and deep link to Bakong app
6. User scans QR with Bakong app and completes payment
7. Bakong sends webhook to confirm payment
8. Payment service updates subscription tier
9. Backend receives update and grants premium access
10. Frontend shows success message
